# 设置页优化实施计划

> 依据：`设置页优化方案.md`（2026-09-20 三轮只读审计产出）。每阶段独立可验证、可回滚。
> 阶段 0（拆分）是纯搬运，**必须单独提交并单独验证**，不与任何功能改动混在一次提交里——拆分后的行号会全变，混提交会让回滚变成二选一。
>
> **全局纪律**
> - 注释解释「为什么」，不复述「做什么」；本轮所有改动都在设置页的读写与展示层。
> - 新逻辑进新模块；`App.tsx`（约 1030 有效行）与 `App.css`（约 4240 有效行）**一行都不加**。
> - 编译验证：`cargo check`（工作目录 `d:\2api\trae-cc\src-tauri`）+ `npx tsc --noEmit`（项目根）。
> - 打包验证必须 `npm run tauri build`，产物约 7.62MB；裸 `cargo build --release` 产出开发态二进制，禁止用于验证（体积少约 0.37MB）。
> - 新增命令三步 checklist：`#[tauri::command]` + `generate_handler!` 注册（`lib.rs:1651-1708`）→ `api.ts` 封装 → `types/index.ts` 同步类型。
> - **不碰时序红线**：`switch_trae_account` 的步骤顺序、`checkin_with_token` 的「claim 前必查 status」、TraeWork 三级关闭与 `GRACEFUL_WAIT_SECS`。
>
> **前置结论（已查证，省去实施时试错）**
>
> 本计划**无需修改任何 capability 文件**。依据是项目已生成的 `src-tauri/gen/schemas/acl-manifests.json` 实测：
>
> | 能力 | 所需权限 | 现状 |
> |---|---|---|
> | 打开所在目录（`revealItemInDir`） | `opener:allow-reveal-item-in-dir` | ✅ 已含于 `opener:default` |
> | 导出文件对话框（`save`） | `dialog:allow-save` | ✅ 已含于 `dialog:default` |
> | 读取版本号（`getVersion`） | `core:app:allow-version` | ✅ 已含于 `core:app:default` |
>
> ⚠️ 唯一例外：**不要用 `openPath`**（打开文件本身），`opener:allow-open-path` 不在默认集内，需要额外配 scope。定位文件用 `revealItemInDir` 即可满足需求。

## 阶段 0：拆分 `Settings.tsx`（纯搬运，不改行为）

**目标**：把 641 行的单文件拆成容器 + 分区组件，为后续所有改动腾出空间（不拆则任何新增都会撞 700 行红线）。

### 任务

1. 新建 `src/pages/settings/`，按下表拆分。**每个 section 只做搬运**，不改 JSX 结构、不改文案、不改交互：

| 文件 | 内容 | 预期有效行 |
|---|---|---|
| `Settings.tsx` | 仅编排：`appSettings` 状态、`updateSettings`、`onToast` 透传 | < 150 |
| `StatusSection.tsx` | 先落一个静态占位（阶段 3.1 补数据） | < 60 |
| `ClientSection.tsx` | TraeCode 路径（含自动扫描）+ 阶段 2.5 后并入 TraeWork 路径 | < 180 |
| `BehaviorSection.tsx` | 隐私模式、自动刷新、刷新间隔、开机静默 | < 180 |
| `MachineIdSection.tsx` | 现「Machine ID」显示 + 清除登录状态（含确认弹窗） | < 220 |
| `DataSection.tsx` | 阶段 2.2 新建 | < 180 |
| `LogSection.tsx` | 现「复制日志」+ 阶段 2.4 扩展 | < 150 |

2. **状态归属规则（防双源）**：`appSettings` 只保留在容器，section 通过 props 接收 `settings` 与 `onPatch(partial, successMessage)`，**section 内不得再存一份本地 settings 副本**——现文件中 `appSettings` 与 `settings` prop 并存（`Settings.tsx:34`、`69-80`）已是双源，拆分时收敛为一处。
3. 抽 `src/pages/settings/IconButton.tsx`：现文件中「刷新 / 复制 / 编辑」三个图标按钮的内联样式几乎一致（`Settings.tsx:234-275`、`330-350`），抽成单一组件，避免拆分后三份重复。
4. 阶段 0 **不动样式归属**：内联 `style` 原样搬走，`Settings.css` 留到阶段 4 收尾统一迁移。理由：搬运与样式重写混在一起，diff 会失去可读性，出问题也无法判断是搬错还是改错。

### 验收

- 界面与拆分前**逐控件走查一致**：Machine ID 显示/刷新/复制、清除登录状态（含确认弹窗）、路径显示/编辑/自动扫描、隐私模式开关、自动刷新开关、刷新间隔下拉、开机静默开关、复制日志。
- `npx tsc --noEmit` 通过；`Settings.tsx` < 150 有效行，各 section 均 < 220 有效行。
- **功能零变化**：两个已知死开关（自动刷新、刷新间隔）此刻仍是死的，不在本阶段顺手修——那属于阶段 1。

### 回滚

单次提交，`git revert` 该提交即可。

## 阶段 1：修正错误（纯前端文案 + 一处后端顺序调整）

**目标**：消除误导性文案与「假成功」交互，不引入新功能。

### 任务

1. **文案修正**（`MachineIdSection.tsx` / `ClientSection.tsx`）：
   - 删「清除 Trae 相关注册表项」——`clear_trae_login_state`（`machine.rs:739-846`）全程只有文件系统操作，写注册表 `MachineGuid` 的只有切换账号路径。
   - 手动删除目录提示改为 `%APPDATA%\Trae CN`。现三处提示（原 `Settings.tsx:284`、`563-565`）分别是 `.trae\`、`Roaming\Trae\`、`Local\Trae\`，在 CN 版下**都指不到实际位置**。
   - Machine ID 提示拆清两个概念：本卡展示的是 Trae 的 `machineid` **文件**（`%APPDATA%\Trae CN\machineid`）；系统 `MachineGuid` 的展示与重置在「机器码」分组（阶段 2.3）。
2. **命名去撞车**：原「自动刷新」改名「定时刷新用量」。它与「开机静默自动刷新 Token」同名相邻，而后者才真实写 `HKCU\Run`。
3. **自动扫描必须落盘**（`ClientSection.tsx`）：扫描成功后补调 `api.setTraePath(found)`，失败要 toast。
   - 为什么必做：现实现只 `setTraePath(path)` 改本地 state，后端 `scan_trae_path`（`machine.rs:322-351`）也不落盘；而 `get_saved_trae_path`（`machine.rs:270-280`）与 `open_trae`（`machine.rs:415-419`）**均不兜底重扫**。结果是「扫到了、界面显示了、重启就没了」，且切换账号时 IDE 打不开、错误只进日志（`lib.rs:1082-1094` 丢弃了 `open_trae` 返回值）。
   - 顺带把 `open_trae` 失败在切换流程中的静默吞错升为 `log::warn`（仅日志级别，不改流程）。
4. **`update_settings` 解耦**（`lib.rs:167-178`）：改为「先落盘设置 → 仅当开关翻转时才写注册表 → 注册表失败只 `log::warn`」。
   - 为什么顺序要反过来：现版本把 `set_auto_start` 放在最前且失败即 `return Err`，导致注册表被安全软件/策略拦截时，「隐私模式」这类无关开关一起保存失败，报错还是「无法打开自启动注册表项」。
   - 为什么失败可以降级：`lib.rs:1639` 启动时会用落盘设置重写一次注册表，下一次启动即自愈。
5. **默认值修正**：若本轮不做阶段 3.3，则把 `auto_refresh_enabled` 默认值三处同步改为 `false`（`lib.rs:57`、`Settings.tsx:28`、`App.tsx:225`）。
   - 为什么：开关默认亮着却没有任何定时器，比没有这个开关更糟——用户会以为用量在自动更新。
6. **清理死封装**（`api.ts`）：删 `addAccount`（`add_account`）与 `updateCookies`（`update_cookies`）——后端从未注册这两个命令（`lib.rs:1651-1708` 无此二者），调用必失败。在 AGENTS.md 的「已移除能力」一节记一笔。

### 验收

- 文案逐条与实际受影响路径/操作对得上，不再出现「注册表」字样。
- **自动扫描 → 重启软件 → 路径仍在**；随后切账号，Trae 能正常打开（这是本阶段最关键的一条）。
- 在注册表写入被拦的环境下（可用组策略或安全软件模拟），切换「隐私模式」开关仍能成功保存。
- `cargo check` + `npx tsc --noEmit` 通过。

### 回滚

纯文案与顺序调整，`git revert` 即可；无数据结构变化。

## 阶段 2：接线已有能力（仅新增 1 个后端命令）

**目标**：把已注册但前端零调用的 11 个命令接进设置页。

### 任务

1. **新增 `get_app_paths` 命令**（本阶段唯一后端改动）：
   - 返回 `{ accounts, settings, logs, traework_profiles }` 四个绝对路径。
   - 数据来源：`AccountManager::get_data_path()`（**需把 `account_manager.rs:61` 改为 `pub fn`**）、`lib.rs` 内的 `get_settings_path()`（同文件可直接用）、`logger::get_log_file_path()`（已 pub）、`traework::profile::profiles_dir()`（已 pub）。
   - 为什么聚合在一个命令里：设置页要一次性渲染整组，四次 invoke 既慢又会让「打开目录」按钮各自处理错误；且路径口径集中在后端一处，避免前端拼接 `%APPDATA%` 字符串。
2. **「数据与备份」分组**（`DataSection.tsx`）：
   - 四个路径条目，各配「复制」与「打开所在目录」（`revealItemInDir`，权限已具备）。
   - 导入 / 导出账号库：**抽共享函数** `src/utils/accountBackup.ts`（复用 `App.tsx` 现有的导入导出逻辑，两处调用同一份，避免复制粘贴出双份行为）。
   - 清空账号库（`clear_accounts`）：红区 + 要求输入确认词（如账号数或「清空」）后才启用按钮。参照现有 `ConfirmModal` 的视觉语言，不要自造样式。
3. **「机器码」分组**（`MachineIdSection.tsx` 拆分或新增 `MachineCodeSection.tsx`）：
   - 两张卡并列：系统 `MachineGuid`（`get_machine_id`）与 Trae `machineid`（`get_trae_machine_id`），各带复制。
   - 重置按钮放次级位置并说明影响：系统 `MachineGuid` 需管理员权限（非管理员时 `set_machine_guid` 返回「无法打开注册表（需要管理员权限）」，命令层**不吞错**，直接展示该错误即可，**无需新增权限探测命令**）。
   - 为什么重置要次级：切换账号时写入的是**账号级绑定的 `machine_id`**，会覆盖系统 `MachineGuid`；本卡的价值主要在「看清现状」，重置属低频操作，不宜与复制同权重。
   - `set_trae_machine_id` 暂不接 UI（本页只展示 Trae `machineid`），保持接口闲置并记入 AGENTS 清单。
4. **日志分组**（`LogSection.tsx`）：`复制`（现有）、`导出`（`save()` 选路径 → `export_logs_cmd`）、`打开日志目录`（`revealItemInDir`）、`清空`（二次确认 → `clear_logs_cmd`）。
5. **客户端路径分组**：把 TraeWork 路径（`traework_set_path` / `traework_scan_path`）并入 `ClientSection.tsx`，与 TraeCode 路径并列；`TraeworkPanel` 内的入口**保留**（面板内操作路径更顺手，两处写同一份配置不会互相覆盖）。
6. **关于页**（`About.tsx`）：版本号改用 `getVersion()`（`@tauri-apps/api/app`，权限已具备），加「检查更新」按钮（`check_update` / `install_update`，`tauri-plugin-updater` 已装配于 `lib.rs:1644`）。`auto_update_check` 字段的处置见阶段 3。

### 验收

- 「打开所在目录」对四个路径都能正确定位（`revealItemInDir` 高亮文件而非仅打开文件夹）。
- 导出日志得到的文件内容包含历史轮转（`export_logs` 会追加 `app.log.1..5`）。
- 清空账号库在未输入确认词时按钮为禁用态；执行后账号列表为空且 `accounts.json` 被重建。
- 非管理员运行点「重置系统机器码」→ 出现明确的权限错误提示，不是静默失败或「操作成功」。
- TraeCode / TraeWork 两处路径设置互相不覆盖，面板刷新后显示一致。
- `cargo check` + `npx tsc --noEmit` 通过；关于页版本号与实际版本一致（改 `package.json` 版本后无需改前端）。

### 回滚

新增命令与 UI 均为增量；还原前端调用点即可，`get_app_paths` 留着不影响（无副作用）。

## 阶段 3：新增设置字段（前后端同时改，逐项独立提交）

**目标**：补上缺失的可配置项与状态可见性。

### 任务

1. **状态面板**（`StatusSection.tsx`）：
   - 需要新增 `get_runtime_status` 命令（本阶段唯一新命令的多值聚合）：返回 `trae_running`（`machine::is_trae_running()` 已 pub）、`traework_running`（复用 `traework_overview` 的 `running`）、当前账号、今日签到汇总、上次刷新时间。
   - 为什么值得做：设置页多数操作有前置条件（清登要求 IDE 已关闭、切换要求无进程占用），把前提显示在按钮上方，比写在警告文案里有效。
   - 注意：`is_trae_running` 在非 Windows/macOS 是常量 `false`（`machine.rs:250-253`），前端不要据此断言「未运行」。
2. **`auto_checkin_enabled`**（默认 `true`）：
   - 现状是 `App.tsx:290-319` 挂载后**无条件**调用 `auto_checkin`，用户无法关闭。加字段后在 `App.tsx` 的该 `useEffect` 加一层判断（这是本轮唯一允许改 `App.tsx` 的一行，且是条件包裹而非新增逻辑）。
   - `--silent` 路径（`handle_silent_start`）**不加判断**：无头模式下没有界面，签到静默失败不影响用户，保持现有行为。
3. **`refresh_interval`** + 真定时器：
   - 前后端同时加字段（Rust `AppSettings` + TS `AppSettings`），并把下拉框接上 `value`/`onChange`。
   - ⚠️ **只补 `value`/`onChange` 是无效的**——那只是把「装饰」变成「能存但不生效」。必须同时实现定时器消费：复用 `App.tsx` 的 `refreshUsageForAccounts`。
   - 并发约束（硬要求）：定时器必须处理与 `switch_account` 的竞争——该路径是全仓唯一「持锁做网络请求」的特例（AGENTS §5.2）。实现要点：`setInterval` + `visibilitychange` 暂停 + 切换进行中跳过本轮，避免定时器在切换窗口期发起额度请求。
   - 若本轮不做，则阶段 1.5 的「默认值改 `false`」不能省。
4. **`theme` 并入 `AppSettings`**：
   - 现状存 `localStorage`（`ThemeSwitcher.tsx:7`），与 `settings.json` 两套存储，导致「导出配置」永远不完整。
   - 迁移策略：读 `settings.json` 的 `theme` 优先；为空时回退读 `localStorage` 的 `trae_theme_v1` 并写回 settings，之后不再写 localStorage。

### 验收

- 状态面板数据与实际一致：开/关 Trae 后刷新，`trae_running` 跟随变化。
- 关闭「自动签到」后重启软件 → 不产生签到请求（看日志有无签到行）；开启后恢复。
- 「刷新间隔」改动后重启仍是新值，且到点真的刷新（可用 1 分钟档临时验证，验证完改回）。
- 切换账号过程中，定时器不发请求（切换期间日志无额度请求）。
- 主题在两个存储中收敛：清空 `localStorage` 后重启，主题仍按 `settings.json` 生效。
- 回归：切换账号（含隐私模式分支）、三种签到入口、TraeWork 保存/切换各跑一次。

### 回滚

所有字段均 `#[serde(default)]`，还原代码后旧数据可读；`theme` 字段残留无害。
