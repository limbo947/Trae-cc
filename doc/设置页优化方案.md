# 设置页优化方案

> 依据：2026-09-20 对设置页的三轮只读审计（截图为起点，逐控件向下核查到后端实现）
> 审计范围：`src/pages/Settings.tsx`、`src/App.tsx`、`src/api.ts`、`src/types/index.ts`、`src-tauri/src/lib.rs`、`machine.rs`、`autostart.rs`、`checkin.rs`、`traework/`
> 结论先行：**设置页的问题不是「功能太少」，而是「该在设置页的能力一个都没接，同时挂着两个不生效的开关」**。已注册命令中有 11 个在前端没有任何调用者，而设置页只有 9 个控件。

---

## 1. 现状盘点

### 1.1 控件有效性判定（实测）

| 控件 | 判定 | 链路 / 问题 |
|---|---|---|
| Machine ID 显示 + 刷新 + 复制 | ✅ 有效（**只读**） | `get_trae_machine_id` 读 `%APPDATA%\Trae CN\machineid`（`machine.rs:96-109`） |
| 清除登录状态 | ✅ 有效，文案有假 | `clear_trae_login_state`（`machine.rs:739-846`）全程**无注册表操作** |
| 安装路径 显示 + 编辑（✎） | ✅ 有效 | `set_trae_path` 校验存在 + `.exe` 后缀，落盘 `config/trae_path.txt` |
| 自动扫描 | ⚠️ **半有效：扫得到、存不下** | 前端只 `setTraePath` 更新 state，未调 `api.setTraePath`；`get_saved_trae_path`（`machine.rs:270-280`）与 `open_trae`（`machine.rs:415-419`）**均不兜底重扫** |
| 自动开启隐私模式 | ✅ 有效 | `privacy_auto_enable` 在 `switch_account` 命令层被消费（`lib.rs:1037`） |
| 自动刷新 | ❌ **无效（死开关）** | 字段零消费方；全仓唯一 `setInterval` 是 TraeWork 面板计时器 |
| 开机静默自动刷新 Token | ✅ 有效 | `autostart::set_auto_start` 写 `HKCU\...\Run` 的 `"exe" --silent`（`autostart.rs:9-31`） |
| 刷新间隔 | ❌ **完全无效（纯装饰）** | `Settings.tsx:476-481` 的 `select` 无 `value`/`onChange`，后端无该字段 |
| 复制日志 | ✅ 有效 | `get_logs(100)` + 剪贴板 |

### 1.2 能力闲置清单（已注册但前端零调用）

以下命令在 `lib.rs:1651-1708` 已注册，但前端没有任何调用者：

| 命令 | 本应归属 |
|---|---|
| `get_machine_id` / `reset_machine_id` / `set_machine_id` / `bind_account_machine_id` | 设置页「机器码」分组 |
| `set_trae_machine_id` | 同上（Trae 侧） |
| `export_logs_cmd` / `clear_logs_cmd` / `get_log_file_path_cmd` | 设置页「日志」分组 |
| `clear_accounts` | 设置页「数据与备份」分组 |
| `check_update` / `install_update` | 关于页（`tauri-plugin-updater` 已装配但无 UI） |

另有**死封装**（`api.ts` 有函数、后端从未注册，调用必失败）：`addAccount`（`add_account`）、`updateCookies`（`update_cookies`）。

### 1.3 文案与实现不符

1. **虚假声明**：确认框写「清除 Trae 相关注册表项」（`Settings.tsx:551`），但 `clear_trae_login_state` 只有文件系统操作。写注册表 `MachineGuid` 的只有切换账号路径。
2. **路径指错**：手动删除提示为 `.trae\` / `AppData\Roaming\Trae\` / `AppData\Local\Trae\`（`Settings.tsx:284`、`563-565`），本项目仅适配 CN 版，真实目录是 `%APPDATA%\Trae CN`。
3. **语义混淆**：页面展示的是 Trae 的 `machineid` 文件，而「需管理员身份运行」实际对应系统注册表 `MachineGuid`——两个不同源的值被并排暗示。
4. **命名撞车**：「自动刷新」（用量数据，且是死开关）与「开机静默自动刷新 Token」（真实生效）同组相邻，用户无法区分。

### 1.4 结构与保存模型问题

- **危险操作与日常配置同权重**：清除登录状态与隐私模式开关在视觉上并列，没有危险区。
- **两套应用的路径配置分居两页**：TraeCode 路径在设置页，TraeWork 路径在面板内。
- **存储位置不可见**：账号库、设置、日志、TraeWork 快照四处分散，换机迁移与排障只能靠文档。
- **保存耦合**：`update_settings`（`lib.rs:167-178`）把自启动注册表写入放在最前，失败即 `return Err`，导致「隐私模式」「自动刷新」等无关开关一起保存失败，报错却是「无法打开自启动注册表项」。
- **全量覆盖写盘**：前端每次 toggle 都提交完整 `AppSettings`，配合 Rust 的 `#[serde(default)]`，会把前端不认识的字段（如 `auto_update_check`）重置为默认值。

### 1.5 真实功能缺口

**自动签到无法关闭**：`App.tsx:290-319` 在挂载后无条件调用 `auto_checkin`（仅按 `last_checkin_date` 去重），没有任何设置字段可以关闭它。这不是「没暴露」，而是「做不到」。

## 2. 目标结构

设置页重组为六组，顺序按「越靠下越危险」：

```
1. 状态        ← 新增：IDE/TraeWork 是否运行、当前账号、今日签到、上次刷新时间
2. 客户端      ← TraeCode 与 TraeWork 路径并列（含自动扫描，扫描后即落盘）
3. 行为        ← 隐私模式、定时刷新用量（含间隔）、自动签到、开机静默刷新 Token
4. 机器码      ← 新增：系统 MachineGuid 与 Trae machineid 双卡，各带复制/重置
5. 数据与备份  ← 新增：三个存储位置 + 打开目录、导入/导出、清空账号库（危险区）
6. 日志更新    ← 复制/导出/打开目录/清空日志 + 版本与检查更新
```

设计要点：

- **前置条件写在按钮旁**，不写在警告文案里。清除登录状态要求 IDE 已关闭——状态面板就在上方，直接呈现。
- **危险操作集中在最底部**，红区 + 二次确认（清空账号库要求输入确认词）。
- **每个开关必须有消费方**，没有消费方的开关不允许上线（本轮两个死开关的根因就是这条约束缺失）。

## 3. 分阶段实施

### 第一阶段：修正错误（纯前端 + 文案，零风险）

| # | 改动 | 文件 | 验收标准 |
|---|---|---|---|
| 1.1 | 删「清除 Trae 相关注册表项」；删除目录提示改为 `%APPDATA%\Trae CN` | `Settings.tsx:551`、`284`、`563-565` | 文案与实际受影响路径逐条对得上 |
| 1.2 | Machine ID 提示拆清两个概念：本页展示值 = Trae `machineid` 文件；系统机器码在下方「机器码」分组 | `Settings.tsx:278-293` | 不再出现「修改 Machine ID」指向注册表却展示文件的错位 |
| 1.3 | 「自动刷新」改名「定时刷新用量」；「刷新间隔」与开关合并为一行 | `Settings.tsx:402-483` | 两个「自动刷新」不再同名相邻 |
| 1.4 | **自动扫描后立即持久化**（补 `api.setTraePath`），失败要 toast 提示 | `Settings.tsx:130-143` | 扫描成功 → 重启软件 → 路径仍在；再切账号 IDE 能正常打开 |
| 1.5 | `update_settings` 改为按字段 patch，自启动写入失败降级为警告、不阻断其余字段 | `lib.rs:167-178` | 注册表被拦时，隐私模式开关仍能保存成功 |
| 1.6 | 清理死封装 `addAccount` / `updateCookies` | `api.ts:16-18`、`122-124` | grep 无残留；`update_cookies` 未注册的事实写进 AGENTS |

> ⚠️ 1.3 若短期不做真正的定时刷新，**必须把 `auto_refresh_enabled` 默认值改为 `false`**（`lib.rs:57`、`Settings.tsx:28`、`App.tsx:225` 三处同步）。默认 `true` + 不生效比没有这个开关更糟。

### 第二阶段：接线已有能力（前端为主，一个新的小命令）

| # | 改动 | 依赖 | 验收标准 |
|---|---|---|---|
| 2.1 | 「数据与备份」分组：展示账号库 / 设置 / 日志三个路径，各配「打开所在目录」 | **需新增 `get_app_paths` 命令**（日志路径已有 `get_log_file_path_cmd`，账号库与设置路径未暴露） | 三个路径均可复制并能在资源管理器中定位 |
| 2.2 | 导入 / 导出账号库入口（从添加弹窗补一份到设置页） | `import_accounts`、`export_accounts_to_path` | 两处入口行为一致 |
| 2.3 | 清空账号库（红区 + 输入确认） | `clear_accounts` | 未输入确认词时按钮禁用 |
| 2.4 | 「机器码」分组：并排展示系统 `MachineGuid` 与 Trae `machineid`，各带复制/重置，并标注当前是否具备管理员权限 | `get_machine_id`、`get_trae_machine_id`、`reset_machine_id`、`bind_account_machine_id` | 非管理员时重置按钮给出明确失败提示，不再静默 |
| 2.5 | 日志区补齐「导出 / 打开目录 / 清空」 | `export_logs_cmd`、`get_log_file_path_cmd`、`clear_logs_cmd` | 四个按钮均可用 |
| 2.6 | TraeWork 路径并入「客户端」分组（面板内入口保留） | `traework_set_path`、`traework_scan_path` | 两处设置互不覆盖，面板刷新后一致 |
| 2.7 | 关于页：版本号动态读取 + 「检查更新」 | `check_update`、`install_update` | 不再硬编码 `v1.0.5`（`About.tsx:11`） |

### 第三阶段：新增设置字段（需前后端同时改，建议单独立项）

| # | 字段 | 动机 |
|---|---|---|
| 3.1 | `auto_checkin_enabled`（默认 `true`） | 补上「自动签到无法关闭」的缺口（见 1.5） |
| 3.2 | `refresh_interval`（分钟） | 与 1.3 配套；**必须前后端同时加字段并接入真正的定时器**，只给 `select` 补 `value`/`onChange` 仍然无效 |
| 3.3 | `theme`（`light` / `dark`） | 现存 `localStorage`（`ThemeSwitcher.tsx:7`），与 `settings.json` 两套存储；不合并则「导出配置/备份」永远做不完整 |
| 3.4 | 状态面板数据（无需新增字段，读取现有命令） | IDE / TraeWork 运行状态、当前账号、今日签到结果、上次刷新时间 |

> 3.2 的实现有前置约束：定时器必须处理与 `switch_account` 的并发——该路径是全仓唯一「持锁做网络请求」的特例（见 AGENTS §5.2），裸 `setInterval` 会与其互相拖慢。需配合 `visibilitychange` 暂停，并避开切换窗口期。

## 4. 明确不做

1. **不把内部调参暴露为设置项**：签到批次重试 `RETRY_WAITS_SECS = [30, 90]`（`checkin.rs:38-39`）、冷却策略表（`checkin_guard.rs`）、TraeWork `GRACEFUL_WAIT_SECS = 8`（`profile.rs:26`）——每一条都对应一次事故（见 AGENTS §5.8、§5.9）。暴露给用户只会制造支持成本。
2. **不重构 TraeWork 快照白名单**：收窄白名单已有实测依据（483MB 可再生缓存），与设置页无关。
3. **不改任何切换/签到时序**：本次所有改动都在设置页的读写与展示层，不触碰 `switch_trae_account` 的步骤顺序、`checkin_with_token` 的「claim 前必查 status」红线、TraeWork 的三级关闭。
4. **不为设置页引入新的全局状态库**：现有 `appSettings` 透传模式够用，问题在字段缺失而非状态管理。

## 5. 文件组织与规模约束

`Settings.tsx` 现 **641 行**且内联 `style` 密集，直接叠加上述内容会撞项目 700 行红线。拆分方案：

```
src/pages/settings/
├── Settings.tsx            # 仅编排 + updateSettings 单点写出
├── StatusSection.tsx       # 状态面板
├── ClientSection.tsx       # TraeCode / TraeWork 路径
├── BehaviorSection.tsx     # 开关类设置
├── MachineIdSection.tsx    # 双机器码卡
├── DataSection.tsx         # 数据与备份（含危险区）
├── LogSection.tsx          # 日志 + 更新
└── Settings.css            # 从内联 style 迁出
```

同时把内联 `style` 迁到 CSS——现有 `Settings.tsx` 里大量重复的按钮样式（刷新/复制/编辑三个图标按钮样式几乎一致）在拆分时应抽成一个共用组件。

## 6. 验证方式

- **每个开关都要有行为断言**：改完一个开关，必须能指出「哪个文件哪一行读它」。三步走：改设置 → 重启软件 → 观察行为变化。
- **持久化验证**：涉及落盘的操作（路径扫描、设置项）都要做「重启后仍在」的验证，不能只看界面回显。
- **失败路径验证**：非管理员运行、Trae 正在运行、注册表被拦三种环境下，设置页必须给出可见反馈而非静默失败。
- **回归范围**：切换账号（含隐私模式分支）、签到（三入口）、TraeWork 保存/切换各跑一次。

## 7. 待决策事项

1. **「自动刷新」是补实现还是关默认值**？倾向补实现（3.2），但涉及并发约束，宜单独一轮。
2. **`auto_update_check` 归属**：Rust 有字段、TS 无、无消费方。倾向从 Rust 删除，或与 2.7 一起接上更新链路后补进 TS——不做半成品。
3. **是否把 `--silent` 刷新 Token 与自动签到拆成两个独立开关**？当前两者都挂在「开机静默」这一条路径上，无法单独关闭其中一个。
4. **AGENTS.md 需同步的两处漂移**（本轮实测）：命令总数记为 55（实为本地 47 + TraeWork 9 = 56）；`traework/commands` 记为 7 个命令（实为 9 个）。建议本次一并修订，并新增一节「已注册但无 UI 入口的命令」，省去下次重新推导。
